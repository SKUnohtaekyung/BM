# 시각화 우선 (Visual-First) — 텍스트로 나열하지 말고 보여줘라 ★

이 스킬의 핵심 원칙. **슬라이드를 만들기 전에 매번** "이 정보, 글보다 도형이 낫지 않나?"를 먼저 묻는다.
좋은 강의덱은 개념의 **구조(관계·흐름)를 눈에 보이게** 만든다. 불릿 나열은 마지막 수단이다.

## 본보기 — BM 9번째 슬라이드 (S07)

전달할 내용: *"비즈니스 모델은 수익 모델을 포함한다. BM에는 고객·문제·가치·전달·비용·수익이 있고, 수익 모델은 그중 한 조각."*

- ❌ **텍스트 버전**: "BM ⊃ 수익모델" + 불릿 6개.
- ✅ **실제 채택**: **동심원 벤 다이어그램** — 바깥 원(비즈니스 모델) 둘레에 5개 태그(고객/문제/가치/전달/비용), 안쪽 원(수익 모델 = 오늘의 주제). *포함 관계*가 한눈에 보인다. → `venn-slide`

정보가 "관계"면 관계를 그린다. 이게 시각화 우선이다.

## 판단표 — 정보의 모양 → 도형

| 정보가 이런 모양이면 | 시각화 | 레이아웃 클래스 |
|---|---|---|
| **포함 / 부분-전체** (A는 B의 일부) | 동심원·벤 | `venn-slide` |
| **두 주체 / 대비** (쓰는 사람 vs 내는 사람) | 좌우 2카드 + 배경 | `actor-slide` |
| **두 개념 정식 비교** (A vs B, 한쪽 추천) | 좌우 2패널(한쪽 강조) | `compare-slide` |
| **순서 / 흐름 / 단계** (1→2→3→4) | 스텝 카드 + 화살표 | `flow-slide` (`.flow-steps-2` / `.work-steps`) |
| **활동 보드 / 분해** (질문 4개로 뜯어보기) | 카드 보드 | `reverse-slide` |
| **캔버스 / 격자 전체** (9칸을 한 장에) | 그리드 보드 | `lean-slide canvas-fill` |
| **조건 → 위험 → 대응** (가정 검증) | 세로 3단 + ↓ | `risk-slide` |
| **여러 지표 + 공식** | 카드 행 + 비율 | `metric-slide canvas-fill` |
| **매핑 A→B** (모델 → 지표) | 열 카드(위 A, 아래 B) | `map-slide` |
| **분류 나열 (많은 항목 훑기)** | 카드 그리드 | `card-grid` (+`wide-12`) |
| **정의 몇 개 비교/정리** | 표 | `tbl canvas-fill` |
| **하나의 큰 질문/선언** | 큰 문장 | `center-msg-a` / `center-msg-b` |

> 실물은 `덱_템플릿킷/layouts/카탈로그.html`, 상황→클래스 전체표는 `덱_템플릿킷/00_레이아웃-선택가이드.md`.

## 텍스트가 맞을 때

모든 걸 도형화하라는 게 아니다. **단순 서술·리드 문장·한 문단 설명**은 `center-v`(좌 본문 + 우 3D 일러스트)가 자연스럽다. 핵심은 *구조가 있는 정보를 텍스트로 뭉개지 않는 것*.

## 카탈로그에 딱 맞는 도형이 없으면

새 도형을 만들어도 된다 — 단 **디자인 토큰을 지킨다**(`덱_템플릿킷/styles/deck.css`, `guide/디자인시스템.md`).
- 프리미티브: 원(`border-radius:50%`)·카드(`.card`)·화살표(텍스트 `→`/`↓`, `--gray-400`)·그리드(`.grid-2/3`)·pill(`.pill`).
- 색은 문법이다: 강조/대상은 코발트 1곳, 오렌지·레드는 문제·경고일 때만.
- 관계를 잇는 **가운데 커넥터**(화살표·라인)를 넣어 두 요소의 관계를 명시한다.
- 새 도형도 슬라이드 헤더(`.s-head`)·eyebrow·제목 골격은 유지한다.

## 체크

슬라이드를 붙인 뒤 스스로 묻는다: "이 장의 정보가 **관계/흐름/구조**인데 불릿으로만 있진 않은가?" 그렇다면 위 표에서 도형으로 바꾼다.
