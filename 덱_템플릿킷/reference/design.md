# SKU LIKELION UX/UI TRACK `design.md`

## 0. 문서 목적

이 문서는 `3주차_UXUI`, `4주차_UXUI`, `5주차_UXUI` PDF 슬라이드의 공통 디자인 요소를 분석하여, 이후 동일한 무드의 PPT 슬라이드를 일관되게 제작하기 위한 디자인 가이드이다.

핵심 목적은 다음과 같다.

- 기존 PDF 슬라이드의 시각적 정체성 유지
- 새 강의 슬라이드를 만들 때 색상, 폰트, 여백, 이미지 스타일이 흔들리지 않도록 기준 제공
- AI 이미지 생성 시 기존 슬라이드와 어울리는 3D 에셋 기준 제공
- PPT, Figma, Canva, AI 슬라이드 생성 도구에서 모두 재사용 가능한 제작 기준 제공

상세 이미지 생성 프롬프트는 `image_generation_prompts.md`에서 별도로 관리한다.

> 주의: PDF 일부는 텍스트가 실제 텍스트 레이어가 아니라 이미지화된 형태로 보인다. 따라서 원본의 정확한 폰트명은 확정할 수 없으며, 시각적 유사도가 높은 대체 폰트 기준으로 정리한다.

## 1. 전체 디자인 콘셉트

### 1.1 핵심 무드 키워드

- 교육용
- 미니멀
- 테크니컬
- 밝은 강의 자료
- 실습 친화적
- 블루 중심의 브랜드 톤
- 3D 아이소메트릭 UI 에셋
- 구조화된 정보 전달

### 1.2 디자인 방향성 한 줄 정의

> 흰 배경과 강한 블루 포인트를 기반으로, 큰 제목과 넓은 여백, 3D UI 에셋, 실습형 캡처를 조합해 초보자가 UX/UI 개념을 빠르게 이해하도록 만드는 교육형 슬라이드 시스템.

### 1.3 전체 톤

- 기본 톤은 깔끔하고 정돈된 강의 자료.
- 핵심 개념은 큼직한 타이포그래피와 파란색 강조로 전달.
- 어려운 개념은 3D 이미지, 밈 이미지, 실제 캡처로 완충.
- 유머 이미지는 아이스브레이킹, 쉬어가기, 실습 전환처럼 흐름을 환기해야 할 때만 제한적으로 사용.

## 2. 캔버스와 기본 화면 규격

### 2.1 슬라이드 크기

| 항목 | 값 |
|---|---:|
| 비율 | 16:9 |
| 기준 해상도 | 1920 × 1080 |
| PPT 크기 | 와이드스크린 16:9 |
| 주요 제작 단위 | px 기준 권장 |

### 2.2 안전 영역

| 영역 | 권장 값 |
|---|---:|
| 좌측 안전 여백 | 80px 이상 |
| 우측 안전 여백 | 80px 이상 |
| 상단 안전 여백 | 40px 이상 |
| 하단 안전 여백 | 60px 이상 |
| 본문 시작 기준 X | 90px 또는 120px |
| 본문 시작 기준 Y | 160px~230px |

### 2.3 헤더 영역

대부분의 흰 배경 슬라이드는 고정 헤더를 가진다.

| 요소 | 위치 및 규칙 |
|---|---|
| 로고 | 좌측 상단, x 약 55px, y 약 40px, 40~48px 크기 |
| 브랜드 텍스트 | 로고 우측, `SKU LIKELION`, 굵은 산세리프, 검정 |
| 상단 라인 | 브랜드 텍스트 우측에서 시작해 우측 팀명 전까지 이어지는 얇은 블루 라인 |
| 팀명 | 우측 상단, 2줄 구성: `UX/UI Team`, `Official LIKELION at SKU` |

### 2.4 헤더 사용 규칙

- 표지와 마지막 인사 슬라이드를 제외한 대부분의 흰 배경 슬라이드에는 헤더를 유지한다.
- 헤더는 본문보다 시각적으로 약해야 한다.
- 상단 라인은 얇게 유지한다. 두껍게 만들면 본문보다 먼저 보인다.
- 헤더 텍스트는 검정 또는 흰색만 사용한다.
- 로고와 브랜드 텍스트의 위치는 슬라이드마다 바꾸지 않는다.

## 3. 색상 시스템

### 3.1 핵심 컬러 팔레트

| 역할 | 이름 | HEX | 사용 용도 |
|---|---|---:|---|
| Primary Blue | Likelion Blue | `#0066CC` | 제목 강조, 번호 원형, 핵심 키워드, 라인, 버튼 |
| Bright Blue | Electric Blue | `#0072F8` | 큰 강조어, 커버의 `UX/UI`, 강한 액센트 |
| Light Blue | Ice Blue | `#8EC3FF` | 상단 라인, 3D 에셋 하이라이트, 보조 강조 |
| Deep Navy | Deep UI Blue | `#233B66` | 3D 에셋의 어두운 면, 깊이감, 카드 그림자 포인트 |
| Black | Ink Black | `#000000` | 제목, 주요 본문, 표지 텍스트 |
| Charcoal | Cover Charcoal | `#1A1A1A` | 표지 배경 |
| Gray 700 | Body Gray | `#4F4F4F` | 부제, 본문 보조 설명 |
| Gray 400 | Muted Gray | `#9A9A9A` | 캡션, 약한 설명, 비활성 요소 |
| Gray 100 | Surface Gray | `#F3F5F8` | 카드 배경, 캡처 영역, 보조 패널 |
| White | White | `#FFFFFF` | 일반 슬라이드 배경, 카드 내부 |
| Orange | Alert Orange | `#F84818` | 주의, 핵심 문제, 강조 경고, 실습 포인트 |
| Red | Error Red | `#D80000` | 틀린 예시, 금지, 오류 표시 |

### 3.2 색상 사용 비율

#### 일반 흰 배경 슬라이드

- 흰 배경: 70~80%
- 검정/회색 텍스트: 15~20%
- 파란색 강조: 5~10%
- 오렌지/빨강 강조: 3% 이하

### 3.3 의미별 색상 규칙

| 의미 | 색상 | 예시 |
|---|---|---|
| 핵심 개념 | Primary Blue | MVP, User Flow, IA, StoryBoard |
| 강조 문장 | Bright Blue | “지금 가장 먼저 확인해야 할 핵심” |
| 주의/문제/경고 | Orange 또는 Red | “핵심 문제”, “예외 처리”, “틀린 예시” |
| 보조 설명 | Gray 700 | 부제, 설명문, 캡션 |
| 비활성/배경 | Gray 100 | 카드 배경, 이미지 패널 |
| 실습/과제 포인트 | Blue | 과제 안내, 실습 목표 |

### 3.4 금지 규칙

- 슬라이드 하나에 파랑, 오렌지, 빨강을 모두 강하게 쓰지 않는다.
- 본문 전체를 파란색으로 만들지 않는다.
- 오렌지는 “주의” 또는 “문제” 의미가 있을 때만 사용한다.
- 배경색이 흰색일 때 연한 하늘색 텍스트를 본문으로 사용하지 않는다.

## 4. 타이포그래피 시스템

### 4.1 권장 폰트

원본 PDF의 정확한 폰트명은 확인되지 않으므로, 아래 폰트를 기준으로 재현한다.

| 용도 | 권장 폰트 | 대체 폰트 |
|---|---|---|
| 한글 제목 | Pretendard ExtraBold 또는 Bold | Noto Sans KR Bold, Apple SD Gothic Neo Bold |
| 한글 본문 | Pretendard SemiBold 또는 Medium | Noto Sans KR Medium, Apple SD Gothic Neo |
| 영문 제목 | Inter Bold 또는 Pretendard Bold | Helvetica Neue Bold |
| 숫자 | Inter Bold | Pretendard Bold |
| 캡션 | Pretendard Medium | Noto Sans KR Regular |

### 4.2 글자 계층

| 역할 | 크기 | 굵기 | 색상 | 사용 위치 |
|---|---:|---:|---|---|
| Cover Brand | 50~58px | Medium/Bold | White | 표지 `SKU LIKELION` |
| Cover Track | 56~68px | ExtraBold | Blue + White | 표지 `UX/UI TRACK` |
| Cover Week | 58~68px | ExtraBold | White | 표지 `WEEK 3.` |
| Cover Korean Title | 76~90px | ExtraBold | Light Blue | 표지 `기획 & 디자인` |
| Slide Main Title | 58~76px | ExtraBold | Black/Blue | 본문 슬라이드 제목 |
| Section Title | 64~86px | ExtraBold | Black/Blue/Orange | 섹션 전환, 핵심 문장 |
| Sub Title | 36~46px | Bold | Gray 700 | 부제, 영문 보조 제목 |
| Body Large | 30~38px | SemiBold | Black/Gray 700 | 일반 본문 |
| Body | 24~30px | Medium/SemiBold | Black/Gray 700 | 설명문 |
| Caption | 18~22px | Medium | Gray 400~700 | 출처, 캡처 설명 |
| Label | 18~24px | Bold | Blue/Orange/White | 카드 라벨, 태그 |
| Number | 44~64px | ExtraBold | White/Blue | 번호 원형, 단계 번호 |

### 4.3 텍스트 작성 규칙

- 제목은 한 슬라이드의 결론이 되도록 쓴다.
- 제목은 길어도 1~2줄 안에서 끝낸다.
- 본문은 발표자가 설명할 수 있게 짧게 남긴다.
- 핵심 단어 1~2개만 파란색으로 강조한다.
- 경고나 반전은 오렌지/빨강을 사용하되, 남발하지 않는다.
- 본문이 5줄을 넘으면 슬라이드를 분리한다.
- “~해요”, “~봅니다”처럼 강의 친화적인 말투를 사용할 수 있다.

### 4.4 금지 규칙

- 제목과 본문 크기가 비슷하면 안 된다.
- 한 슬라이드에서 굵은 글씨를 너무 많이 사용하지 않는다.
- 의미 없이 모든 키워드를 파란색으로 칠하지 않는다.
- 작은 폰트로 많은 내용을 욱여넣지 않는다.
- AI가 만든 듯한 추상어를 남발하지 않는다. 예: “혁신적인 사용자 경험을 제공합니다”만 단독으로 쓰기 금지.

## 5. 레이아웃 시스템

### 5.1 기본 그리드

- 기준 캔버스: 1920 × 1080
- 기본 좌측 본문 시작선: x 90~130px
- 중앙 본문 기준선: x 960px
- 우측 이미지 영역 시작선: x 1040~1180px
- 하단 안전선: y 980px
- 헤더 높이: 약 100px

### 5.2 대표 레이아웃 패턴

#### A. 표지형 Cover

사용 위치: 각 주차 첫 페이지

구성:

- 검은 배경
- 좌측 상단 로고 + `SKU LIKELION`
- 그 아래 `UX/UI TRACK`
- 좌측 중단 `WEEK n.`
- 좌측 하단에 큰 한글 제목
- 우측 상단 팀 정보
- 우측 하단 3D UI 에셋
- 우측 하단 발표자 이름

규칙:

- 배경은 `#1A1A1A` 유지.
- 3D 에셋은 전체 면적의 30~45%를 차지.
- 에셋은 우측 하단으로 살짝 잘리게 배치 가능.
- 표지에서는 흰색과 파란색만 사용한다.
- 오렌지, 빨강 사용 금지.

#### B. 강의 도입형 Intro

사용 위치: 각 주차 2페이지

구성:

- 흰 배경 + 고정 헤더
- 좌측 상단 작은 주차 문구
- 큰 한글 제목
- 굵은 회색 영문/키워드 부제
- 본문 1~2줄
- 우측 하단 3D 주제 이미지

규칙:

- 제목은 좌측 x 130px 근처에서 시작.
- 우측 이미지는 y 600px 전후부터 배치.
- 본문 문장 안 핵심 표현만 파란색으로 강조.
- 이미지에는 텍스트를 넣지 않는다. 텍스트는 PPT에서 별도로 올린다.

#### C. 과제 확인형 Center Message

사용 위치: 지난주 과제 확인, 핵심 질문

구성:

- 흰 배경 + 고정 헤더
- 중앙 정렬 제목
- 중앙 정렬 큰 메시지
- 강조어만 파란색
- 하단 또는 좌우에 짧은 설명

규칙:

- 중앙 메시지는 1줄 또는 2줄.
- 여백을 넓게 유지.
- 이미지가 있다면 좌측 하단 또는 작은 보조 요소로만 사용.

#### D. 아이스브레이킹형 Mixed Content

사용 위치: 세션 시작 전 이야기 나누기

구성:

- 흰 배경 + 고정 헤더
- 큰 파란색 제목
- 좌측에 카드 또는 이전 슬라이드 캡처
- 우측에 질문 문장
- 하단 또는 우측에 밈/유머 이미지

규칙:

- 유머 이미지는 강의 환기용이므로 슬라이드 전체를 지배하면 안 된다.
- 본문 질문은 검정, 핵심 단어는 오렌지 또는 파랑.
- 밈 이미지에는 그림자나 라운딩을 과하게 주지 않는다.

#### E. 오늘 배울 것 Agenda

사용 위치: 각 주차 초반

구성:

- 좌측: `오늘 배우게 될 것` 제목
- 제목 아래 짧은 파란색 막대
- 제목 아래 1~2줄 설명
- 우측: 1, 2, 3 번호 원형 + 각 항목 제목/설명

규칙:

- 번호 원형은 Primary Blue 배경, 흰색 숫자.
- 항목 제목은 파란색 Bold.
- 항목 설명은 회색.
- 세 항목의 간격은 동일하게 유지.

#### F. 개념 설명형 Text + Illustration

사용 위치: What, MVP, IA, User Flow, StoryBoard 설명

구성:

- 상단 헤더
- 좌측 또는 상단에 제목
- 본문은 2~4개 단락
- 우측 또는 하단에 3D 일러스트
- 필요 시 강조어 파랑/오렌지

규칙:

- 개념 설명은 “정의 → 왜 필요한가 → 어떻게 쓰는가” 순서로 구성.
- 본문은 왼쪽 정렬.
- 3D 이미지는 개념을 보조해야 하며, 장식만을 위해 넣지 않는다.

#### G. 비교형 Compare

사용 위치: 좋은/나쁜 예시, IA/User Flow 비교, Happy/Unhappy Path 비교

구성:

- 제목
- 좌우 2열 또는 3열 카드
- 각 카드 안 아이콘, 키워드, 짧은 설명
- 차이를 보여주는 색상 또는 체크/경고 아이콘

규칙:

- 비교 항목의 카드 크기는 동일하게 맞춘다.
- 좋은 예시는 파랑/초록 계열, 나쁜 예시는 오렌지/빨강 계열.
- 결론 문장은 카드 아래에 크게 배치 가능.

#### H. 튜토리얼 캡처형 Screenshot Guide

사용 위치: ChatGPT, Figma, FigJam 사용법 안내

구성:

- 상단 헤더
- 큰 실제 화면 캡처
- 파란색 화살표
- `클릭!`, `이거!!` 같은 짧은 액션 문구
- 필요 시 단계 번호

규칙:

- 캡처 이미지는 화면의 70~85%까지 크게 사용 가능.
- 화살표는 굵고 파란색으로 사용.
- 텍스트는 짧게. “클릭!”처럼 행동 중심으로 작성.
- 캡처의 핵심 영역을 가리지 않는다.

#### I. 실습 안내형 Practice

사용 위치: 실습, 과제 공지

구성:

- 중앙 또는 좌측 큰 `실습!`
- 실습 목표 1줄
- 작업 목록 2~4개
- 마스코트/밈/작은 캐릭터 이미지

규칙:

- 학생이 해야 할 행동을 가장 크게 보여준다.
- 실습 조건은 번호 목록으로 짧게 정리한다.
- 밈 이미지는 보조 장치로만 사용.

## 6. 컴포넌트 규칙

### 6.1 상단 헤더

| 속성 | 규칙 |
|---|---|
| 높이 | 약 100px |
| 로고 크기 | 40~48px |
| 브랜드 텍스트 | 검정, 44~52px 수준 |
| 상단 라인 | 2~3px, Light Blue |
| 우측 팀명 | 28~34px, 2줄 |

### 6.2 번호 원형

| 속성 | 규칙 |
|---|---|
| 크기 | 90~120px |
| 배경 | Primary Blue |
| 숫자 | 흰색, Bold |
| 사용 위치 | Agenda, 단계 설명, 리스트 |
| 금지 | 번호 원형마다 색상 다르게 쓰기 금지 |

### 6.3 파란색 강조 막대

| 속성 | 규칙 |
|---|---|
| 형태 | 둥근 모서리의 짧은 가로 막대 |
| 길이 | 140~180px |
| 높이 | 14~18px |
| 색상 | Primary Blue |
| 위치 | 제목 아래 20~30px |

### 6.4 카드

| 속성 | 규칙 |
|---|---|
| 배경 | White 또는 Gray 100 |
| 모서리 | 18~28px radius |
| 그림자 | 부드러운 그림자, 투명도 낮게 |
| 내부 여백 | 24~40px |
| 테두리 | 연한 회색 또는 없음 |
| 사용 | 비교, 예시, 기능 목록, 캡처 래핑 |

### 6.5 화살표와 연결선

| 속성 | 규칙 |
|---|---|
| 기본 색상 | Primary Blue |
| 보조 색상 | Red 또는 Orange |
| 두께 | 3~6px |
| 스타일 | 둥근 끝, 직선 또는 부드러운 꺾은선 |
| 사용 | 튜토리얼 클릭 위치, 데이터 흐름, IA/User Flow 연결 |

### 6.6 캡션/출처

- 위치: 슬라이드 하단 또는 이미지 바로 아래.
- 색상: Gray 400~700.
- 크기: 18~22px.
- 중요한 정보가 아니면 작게 둔다.
- 캡션이 본문보다 먼저 보이면 안 된다.

## 7. 이미지 스타일 규칙

### 7.1 사용 이미지 유형

| 유형 | 사용 위치 | 공통 특징 |
|---|---|---|
| 3D 아이소메트릭 에셋 | 표지, 도입, 개념 설명 | 흰색/아이스블루 기반, 둥근 UI 카드, 부드러운 그림자, 파란 포인트 |
| 3D UI 목업 | MVP, StoryBoard, 화면설계서 | 스마트폰/앱 카드/입력창/버튼, 입체감, 화면 텍스트 최소화 |
| 3D 개념 은유 | 길, 지도, 큐브, 체크, 경고 | UX 개념을 길, 구조, 흐름, 경고로 시각화 |
| 3D 캐릭터 | 작업 과부하, 회의, 고민 상황 | 둥근 인체 비율, 흰색/파스텔 톤, 표정은 과하지 않음 |
| 밈 이미지 | 아이스브레이킹, 유머 전환 | 실제 방송/인터넷 밈 캡처, 저해상도 허용 |
| 실제 화면 캡처 | ChatGPT, Figma, FigJam 사용법 | 큰 이미지, 파란 화살표와 짧은 행동 문구 |
| 다이어그램/플로우 | IA, User Flow, 데이터 흐름 | 흰 노드, 파란 연결선, 필요한 경우 빨간 번호 마커 |

### 7.2 공통 3D 이미지 스타일

- 아이소메트릭 또는 약한 3/4 시점.
- 흰색, 연회색, 아이스블루를 기본 재질로 사용.
- 파란색은 버튼, 선, 강조 아이콘, 체크 등에만 사용.
- 형태는 둥글고 부드럽다.
- 그림자는 연하고 넓게 퍼진다.
- 금속보다 반투명 플라스틱, 유리, 젤리 같은 재질에 가깝다.
- 배경은 투명 또는 흰색. 표지에서는 검은 배경 위에 배치 가능.
- 복잡한 배경을 만들지 않는다.
- 이미지 안 텍스트는 최소화한다. 텍스트는 PPT에서 올린다.

### 7.3 이미지 배치 규칙

| 위치 | 사용 방식 |
|---|---|
| 우측 하단 | 도입 슬라이드, 개념 설명 이미지 |
| 중앙 | 과제 확인, 핵심 질문, 큰 메시지 |
| 좌측 하단 | 밈 이미지, 실습 환기 이미지 |
| 우측 40~50% | UI 목업, 비교 예시, 앱 화면 |
| 전체 화면 | 튜토리얼 캡처, Figma/ChatGPT 화면 안내 |

### 7.4 이미지 금지 규칙

- 이미지에 긴 한글 텍스트를 생성하지 않는다.
- 지나치게 사실적인 인물 사진을 3D 에셋과 섞지 않는다. 단, 밈은 예외.
- 3D 에셋에 고채도 무지개색을 사용하지 않는다.
- 배경이 복잡한 이미지를 본문 슬라이드에 크게 넣지 않는다.
- 표지 이미지에 오렌지나 빨강을 넣지 않는다.
- 이미지가 본문을 가리게 배치하지 않는다.

## 8. 이미지 생성 프롬프트 시스템

개별 이미지 생성 프롬프트는 `image_generation_prompts.md`에서 관리한다. `design.md` 본문에는 모든 이미지에 공통으로 적용할 기준만 남긴다.

### 8.1 공통 베이스 프롬프트

```text
Create a clean 3D isometric educational UI illustration for a Korean UX/UI lecture slide.
Use a white, light gray, and ice-blue color palette with strong cobalt blue accents.
Style: soft rounded shapes, glossy translucent plastic and glass material, minimal tech aesthetic, gentle ambient occlusion, soft shadow, high readability, lots of empty space.
Composition: isolated object on transparent or white background, no complex scenery, no realistic photo texture.
Do not include readable text, logos, brand names, watermarks, or tiny UI labels.
The image should match a modern university lecture deck, minimal, friendly, technical, and polished.
```

### 8.2 공통 네거티브 프롬프트

```text
Avoid photorealistic style, complex background, colorful rainbow palette, neon cyberpunk, anime style, flat vector illustration, hand-drawn sketch, 8-bit pixel art, cluttered interface, readable text, Korean text, distorted letters, logos, watermarks, realistic brand UI, excessive shadows, harsh gradients, dark heavy mood, detailed human faces.
```

## 9. 실제 화면 캡처 사용 규칙

### 9.1 캡처 스타일

- 캡처는 실제 툴 사용법을 설명할 때만 크게 사용한다.
- 캡처는 원본 비율을 유지한다.
- 핵심 영역에는 파란색 화살표를 사용한다.
- 설명 문구는 짧게 쓴다. 예: `클릭!`, `여기!`, `이거!!`
- 캡처 위에 너무 많은 주석을 올리지 않는다.

### 9.2 캡처 배치

| 슬라이드 목적 | 배치 |
|---|---|
| 클릭 위치 안내 | 캡처 전체를 크게 배치하고 화살표 1개 |
| 단계 설명 | 캡처 2~3개를 좌우 순서로 배치 |
| 결과 비교 | Before/After 형태로 배치 |
| Figma 구조 설명 | 전체 캡처 + 확대 영역 1개 |

### 9.3 금지 규칙

- 캡처를 작게 여러 개 넣어 읽을 수 없게 만들지 않는다.
- 화살표를 3개 이상 남발하지 않는다.
- 캡처 위에 긴 문장을 올리지 않는다.
- 캡처 화면의 어두운 배경과 슬라이드 흰 배경 사이 여백을 너무 좁히지 않는다.

## 10. 다이어그램과 플로우 규칙

다이어그램은 UX 주제별 작성법보다 슬라이드 안에서의 시각적 일관성이 우선이다.

- 구조형 다이어그램은 위에서 아래로, 흐름형 다이어그램은 좌에서 우로 배치한다.
- 노드는 흰 배경, 얇은 회색 테두리, 18~28px radius를 기본으로 한다.
- 연결선은 Primary Blue를 기본으로 쓰고, 예외나 오류 흐름만 Orange 또는 Red로 구분한다.
- 결정 지점은 다이아몬드 형태를 사용할 수 있으나, 한 슬라이드에 너무 많은 분기점을 넣지 않는다.
- 복잡한 구조는 한 장에 모두 넣기보다 핵심 흐름만 보여주고, 필요하면 확대 슬라이드로 분리한다.
- 화면 번호나 요소 번호가 필요한 경우 `SCR-01`, `1-1`처럼 고정된 형식을 사용한다.

## 11. 문장 스타일 가이드

- 제목은 주제명이 아니라 슬라이드의 결론이 되도록 쓴다.
- 한 슬라이드는 하나의 메시지만 전달한다.
- 본문은 발표자가 말로 풀 수 있을 정도로 짧게 남긴다.
- 어려운 용어는 첫 등장 시 바로 풀어쓴다.
- 개념 슬라이드는 단정하고 명확하게, 실습 슬라이드는 행동 중심으로 쓴다.
- 아이스브레이킹이나 쉬어가기 슬라이드에서만 말투를 조금 풀 수 있다.
- `UX 개념 정리`, `내용 설명`, `기능 소개`처럼 범용적인 제목은 피한다.
- 본문 구조는 가능하면 `정의 → 필요한 이유 → 적용 방식 → 오늘 할 작업` 순서로 정리한다.

- [ ] 슬라이드마다 하나의 핵심 메시지만 있는가?
- [ ] 이미지가 본문보다 과하게 커지지 않았는가?
- [ ] 여백이 충분한가?

### 12.3 이미지 일관성

- [ ] 3D 에셋이 흰색, 아이스블루, 코발트블루 중심인가?

- [ ] 표지 에셋은 검은 배경과 어울리는가?
- [ ] 본문 에셋은 흰 배경에서 자연스럽게 보이는가?
- [ ] 밈 이미지는 목적 있는 환기용으로만 쓰였는가?

- [ ] 제목만 봐도 슬라이드의 핵심이 보이는가?
- [ ] 초보자가 이해하기 어려운 용어는 풀어썼는가?
- [ ] 실습 슬라이드는 무엇을 해야 하는지 바로 보이는가?

- [ ] 흰 배경 위 연한 색 텍스트를 본문으로 쓰지 않았는가?
- [ ] 색상만으로 의미를 전달하지 않았는가?
- [ ] 캡처 이미지가 너무 작지 않은가?
- [ ] PDF 변환 후 텍스트와 이미지가 깨지지 않는가?

## 13. 핵심 요약

이 슬라이드 시스템의 본질은 다음 5가지다.

1. 흰 배경, 검은 제목, 파란 핵심 강조.
2. 상단 고정 헤더로 브랜드 일관성 유지.
3. 큰 제목과 넓은 여백으로 초보자에게 부담을 줄임.
4. 3D 아이소메트릭 UI 에셋으로 개념을 부드럽게 시각화.
5. 실습 파트에서는 실제 캡처, 화살표, 짧은 액션 문구로 바로 따라 하게 만듦.

따라서 새 PPT를 만들 때 가장 중요한 규칙은 “예쁘게 꾸미기”가 아니라 “기존 강의자료의 질서, 여백, 파란색 강조, 3D 에셋 톤을 유지하는 것”이다.
